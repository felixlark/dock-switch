# Quiet tool windows

Keep the Codex main window on its existing `external_fill` placement. Put identified independent tool windows on the rightmost external display without raising a window, activating an app, moving the pointer, changing Spaces, or exiting full screen. App activation by an unrelated tool is outside the placement feature; prevent it at the supported launch entry instead of repeatedly restoring focus.

## Integration

- Add `ToolWindowPolicy.swift` in DockSwitchCore: protected bundles, dedicated utility bundles, rightmost external target (never fall back to the internal display), fitting a window while preserving its size when possible, and excluding sheets/fullscreen/minimized windows.
- Add `ToolWindowRouter.swift` in DockSwitch: own public AX observers for dedicated utility apps and explicitly opened tools; For a mixed-use app, claim only a requested file URL using public AXDocument metadata, then end that document claim. Never grant the process a persistent app-wide rule. A resource without reliable document metadata has no automatic claim and requires tool-place with a known window ID. Never infer ownership from timing or a process being cold. Dedicated process observation is limited to known utility bundle IDs or an explicit --dedicated launch of a tool-only app. If the requested file already has a baseline window, do not create any pending document claim, even if it is later closed and reopened manually. Existing manual windows are baselined before opening a resource. No process-ancestry inference and no blanket Chrome/Safari/TextEdit rules. Protected apps are Codex, X and X Chat.
- Add control commands through the existing server: `tool-open` (app bundle path plus optional resource URL, NSWorkspace OpenConfiguration.activates=false), `tool-place` (PID and public CG window ID; map to exactly one AX window by geometry, reject ambiguity), `tool-status`, `tool-routing` (enabled flag), `tool-exempt` (current focused window), `tool-recover` (only managed offscreen windows). Store only the enabled preference; per-process ownership is session-local and removed on process exit. Never reopen an old resource on restart.
- Expose pause, current-window exemption and offscreen recovery in the existing status menu. Dedicated utility IDs initially cover Dock Switch Settings, Codex Plus Settings and DeskVNCViewer; those are user-facing tool windows, not user browsers or editors. App-created menus, sheets, notification banners and Codex internal overlays remain with their owners.
- Keep existing placement/launcher commands and F6 semantics intact. Quiet movement uses a separate path that does not call the existing Raise/follow behavior. A handled window is not moved again after the user drags it. Screen changes do not rearrange visible existing windows; manual recovery fits managed offscreen windows to a connected external display.
- Extend the installed CLI with the commands, argument validation and JSON acknowledgements. `tool-open` acknowledgement means only launch request accepted; status distinguishes requested, waiting-for-window, placed, observation-unavailable and opened-without-window-rule. Attach observers before opening an existing file document; for a new process attach then enumerate existing windows to close the first-window race. Existing already-managed windows are never claimed again; status/visible windows prove placement, never infer success from launch alone. If no new independent window appears (for example a browser reuses a tab), preserve the existing window and report no new placement.
- Document the actual installed command for generated native tools in the local tool-routing guidance after verification. This complements official Computer Use: it does not replace app interaction or browser automation. Do not modify vendor app signatures or system notification policy.

## Implementation boundaries and validation

Files: the two new Swift files; executable `main.swift`; existing Core control server extension; `bin/dock-switch-cli.js`; policy tests and CLI tests; README and this design. Preserve foreign AGENTS.md changes and installed launcher config. Caches/logs under Library; no new worktree. No extra service or window manager. Native Settings removes its unconditional onAppear activation; normal user launches still use the existing activating NSWorkspace configuration. A tool-open background launch honors activates=false. Track the formerly ignored CLI source because it is required to reproduce the installed control contract. CLI auto-retry is allowed only before any request was sent; a lost post-send acknowledgement is an unknown result, never a replay.

Test policy decisions for no external display, multiple displays, oversize frames, protected bundles and special windows. Test CLI command contract and failures without GUI. Run existing yarn test, build/sign/install only the changed Dock Switch product. Real installed acceptance uses official Computer Use to prepare/observe the foreground and KVM for any required hardware hotkey: background open an actual tool document while a temporary draft has focus, record foreground activation events throughout cold and warm opens, inspect focused draft and pointer before/after, verify right-screen geometry, multiple-window handling, manual-move preservation, pause/exemption and F6 still targeting the middle display. Sheets staying with the parent are expected, not a failure. Physically disconnected-display behavior is reported untested unless actually exercised; pure policy tests do not prove hotplug. Keep user drafts and unrelated windows unchanged.

The target external display is bound by system UUID on first use, so unplugging it does not silently promote the center Codex display into the tool area. Pending windows can retry when that same display reconnects; handled visible windows are left alone. Manual recovery is explicit. Acceptance also opens an unrelated manual window in a mixed-use app after a tool document has been claimed; that window must remain untouched.

Review fixes: ordinary cold apps default to no app-wide rule; non-file/no-URL completion never claims a temporal window delta; baseline document identity prevents stale reopen claims. Regression tests cover all three decisions. The installed build entry uses system /bin/bash explicitly: the Homebrew bash on this host blocked writing a plist heredoc before cat started; no installed app had been changed at that stall.

## Installed acceptance, 2026-11-14

- 106 Node tests and 61 non-GUI Swift tests passed. The signed 1.1.0 app was installed from this candidate, with the existing launcher configuration preserved byte-for-byte.
- Official Computer Use opened and inspected real native tool windows and prepared an empty X Chat draft. Continuous application-activation notifications plus foreground/focused-element observations covered separate cold and warm opens. The clean cold run retained the same X Chat text area, test draft and pointer position; the clean warm document/Settings run retained X Chat and its text area with no activation events. Artificial test text was cleared without sending.
- Live public window geometry confirmed Codex on the middle external display and the independently placed windows entirely within the right external work area. An existing manual window, created through the actual editor UI and positioned through the product's normal control entry, stayed in the middle after another tool document opened. The user's pre-existing editor windows retained their original positions.
- Reopening an already open test document returned `opened-in-existing-window`, with no new file rule. Pause removed all AX observers; resume returned to enabled operation. Test-only documents and the empty manual test window were closed through official Computer Use.
- Independent review findings about process-wide ownership, temporal window claims, document/tab reuse, repeated baselines, lost acknowledgements, containment readback and result labels were addressed. The final targeted read-only check found no new material ownership/window-destruction issue.
- Physical display disconnection and hardware F6 were not retested. The available KVM was confirmed connected to a different computer and was left untouched. Native sheets/fullscreen exclusions have policy coverage; that does not stand in for all-app UI coverage. Existing intentional launcher activation remains unchanged.
